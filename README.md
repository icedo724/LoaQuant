# 로스트아크 경제 시계열 분석

## 주요 거래품목 시세 분석
GitHub Actions를 활용해 로스트아크 경매장의 주요 품목 최저가를 **1시간 주기**로 자동 수집하고 시각화합니다.
수집은 예약된 주기대로 항상 성공하지는 않으므로, 대시보드 상단에 **실제 수집률과 간격**을 함께 표시합니다.

### 자동 가격 수집 대상
1. **T3/T4 강화 재료**
2. **생활 재료**
3. **배틀 아이템**
4. **유물 각인서**
5. **T4 8레벨 이상 보석**

### 수동 업데이트
- 골드 가격

### 서비스 링크
수집된 데이터는 Streamlit을 통해 대시보드에서 실시간으로 확인할 수 있습니다.

- **[LoaQuant 바로가기](https://loaquant.streamlit.app/)**

- **[대시보드 기능소개](https://www.notion.so/miniminimin/LoaQuant-325fbcdaed2880b18277ddcee3881459?source=copy_link)**

### 주요 기능
**1. 시세 추적**
- 수집 시점 그대로의 최저가 흐름 차트 제공
- **로아 서버 기준(매일 오전 06시 ~ 다음날 06시)** 을 하루로 보는 일평균 가격 제공.
  이 경계는 `common/timeaxis.py` 한 곳에 정의되어 대시보드와 분석 모듈이 같은 값을 씁니다
- 그날 수집 횟수를 함께 표시해, 표본이 적은 날의 평균을 구분할 수 있게 함
- 전일 대비 등락폭 및 가격 변동 표시

**2.  시장 분석**
- **RSI(14일)** 및 **볼린저 밴드(20일)** 를 게임일 축에서 계산.
  수집 간격이 불규칙하므로 시간별 원본이 아니라 일 단위 등간격 축에서 산출합니다
- **과매수(고점)/과매도(저점)** 구간 탐지. 표본이 부족한 구간에서는 신호를 내지 않습니다
- 직관적인 시장 분석 리포트 카드 UI 제공
- 현금 가치 확인 기능 제공. **환율이 없는 날짜는 임의로 메우지 않고 비워 둡니다**
- 예측은 `analysis/backtest.py` 의 롤링 오리진 결과로 품목마다 모델을 고르고,
  화면에 **명목 구간과 함께 실측 커버리지·MAPE** 를 표시합니다


**3. 시각화 및 유틸리티**
- **정기 점검 시각화**: 매주 수요일 점검 시간(06:00~10:00) 차트 내 회색 영역 표시
- **이벤트 추적**: 주요 이벤트 종료 일자 그래프 내 마킹
- **교환 효율 계산**: 하위 재료 ↔ 상위 재료 교환 시 손익(골드 가치) 자동 비교 분석.
  교환비는 코드에 적힌 가정값이며 화면에 함께 표시합니다 (수수료 미반영)
- **패치분석실**: 패치 이전 데이터로 학습한 반사실 가격과 실제 가격을 비교.
  차이뿐 아니라 **예측구간을 벗어난 일수**를 함께 보고하고, 같은 날 다른 이벤트가 있으면 경고합니다

### 대시보드·분석 검증

시간 축과 집계식이 깨지면 화면의 숫자가 조용히 틀린다. 검증을 붙여 두었다.

```bash
python tests/test_timeaxis.py    # 게임일 경계, 지표 축, 요일 효과
python tests/test_analysis.py    # 예측구간, 환율 환산, 거래대금
```

예측 모델 선택은 주석이 아니라 측정으로 정한다. 아래를 실행하면 품목별 MAPE 와
실측 예측구간 커버리지를 재서 `analysis/model_registry.json` 에 기록하고,
대시보드가 그 결과를 읽어 모델을 고르고 커버리지를 함께 표시한다.

```bash
python analysis/backtest.py --horizon 1
```

## 데이터 수집 정책

로스트아크 오픈 API의 호출 한도는 **분당 100회**다. 수집기는 이 한도 아래에서 동작하도록
`common/api_client.py` 한 곳에서 호출 간격과 재시도를 통제한다.

| 항목 | 값 | 근거 |
|---|---|---|
| 호출 간격 | 분당 95회 (요청당 0.63초) | 한도 100회에 안전 여유를 둔 값 |
| 재시도 | 최대 4회, 지수 백오프 (5→10→20→40초) | 고정 간격 재시도는 한도를 계속 두드리게 된다 |
| `Retry-After` | 서버가 지정한 값을 그대로 대기 | 상한으로 자르면 지시보다 일찍 재요청하게 된다 |
| 대기 상한 초과 | 재시도하지 않고 해당 요청 포기 | 일찍 두드리는 것보다 포기가 낫다 |
| 연속 실패 | 5건 누적 시 수집 중단 | API 응답 불가 상태에서 수백 건을 계속 시도하지 않는다 |
| 동시 실행 | 워크플로 `concurrency` 로 차단 | 실행이 겹치면 같은 키로 동시 호출해 한도를 초과한다 |
| 실행 시간 | `timeout-minutes: 20` | 정상 실행은 약 5분. 다음 정시 실행 전에 종료되도록 한다 |

한 번의 실행에서 발생하는 요청은 약 428건(시세 97 + 거래량 331)이며, 위 간격 기준으로 약 4.5분이 걸린다.

정책이 깨지면 곧바로 이용 한도 위반으로 이어지므로 검증을 붙여 두었다.

```bash
python tests/test_api_client.py
```
